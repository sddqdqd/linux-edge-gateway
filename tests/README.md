# 测试与压测规划

## 1. 协议层单元测试（第 1 周）

建议编写轻量 C++ 测试程序验证 `RingBuffer` 与 `FrameCodec`：
- 正常编码与解码往返一致
- 半包喂入（每次仅写入 1~3 字节）能否正确重组
- 粘包喂入（连续写入 5 帧）能否依次全部解出
- 帧头前混入脏数据 / 中间翻转 1 bit 导致 CRC 错误时，能否自动滑窗恢复并正确解析后续有效帧
- 超长非法 `PayloadLen > 4096` 不会被卡死或触发越界分配

## 2. Python 自动化网络压测客户端（第 3 周）

建议在 `tests/stress_client.py` 中实现以下测试用例：
1. **功能验证**：依次发送 Ping(`0x01`)、查询状态(`0x02`)、控灯(`0x03`)、查统计(`0x04`) 并校验回包 CRC 与状态码。
2. **半包注入**：将单个请求帧按随机切片分多次 `send()`，中间加短延迟。
3. **粘包注入**：将 20 个请求帧拼接后一次 `send()`，验证服务端全部返回对应 `Seq`。
4. **异常断连与心跳超时**：建立连接后不发任何数据，验证超过 `heartbeat_timeout_sec` 后被服务端自动断开清理；建立连接发半个包后直接强杀客户端，验证服务端不崩溃、不泄漏 fd。
5. **并发压测**：启动 30~50 个并发连接持续高频请求 10 分钟以上，在板端观察 `/proc/<pid>/status` 中 `VmRSS` 与 `/proc/<pid>/fd` 数量是否稳定。
