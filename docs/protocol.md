# 二进制通信协议规格书（V1）

本文档定义边缘网关与局域网运维/控制客户端之间的 TCP 二进制通信协议。设计目标：紧凑、可抗粘包/半包、支持脏数据重同步、跨平台字节序安全，并为 V2 扩展预留命令字空间。

---

## 1. 帧格式定义

所有多字节整数字段（`Length`、`Seq`、`CRC16` 及载荷内整数）一律采用 **网络字节序（大端，Big-Endian）**。  
严禁直接对 C/C++ 结构体做 `memcpy` 发送，必须按字段显式编解码。

```text
+------------+------------+------------+------------+------------+-----------------+------------+
|   Magic    |  Version   |    Cmd     |    Seq     | PayloadLen |     Payload     |   CRC16    |
|  2 Bytes   |  1 Byte    |  1 Byte    |  2 Bytes   |  2 Bytes   | 0 ~ 4096 Bytes  |  2 Bytes   |
+------------+------------+------------+------------+------------+-----------------+------------+
|<--------------------------------- CRC16 计算范围 -------------------------------->|
```

### 字段说明

| 字段 | 长度 | 取值与说明 |
| :--- | :--- | :--- |
| `Magic` | 2 Bytes | 固定帧头魔数：`0xAA 0x55`（高字节 `0xAA`，低字节 `0x55`） |
| `Version` | 1 Byte | 协议版本号，V1 固定为 `0x01` |
| `Cmd` | 1 Byte | 命令字（请求为 `0x01 ~ 0x7F`，对应响应为 `ReqCmd \| 0x80`） |
| `Seq` | 2 Bytes | 请求序列号（uint16 大端），服务端响应时原样回传，便于客户端异步匹配 |
| `PayloadLen` | 2 Bytes | `Payload` 字节数（uint16 大端），合法范围 `0 ~ 4096` |
| `Payload` | N Bytes | 变长载荷，内容由 `Cmd` 决定 |
| `CRC16` | 2 Bytes | 采用 **CRC-16/MODBUS**（多项式 `0xA001`，初始值 `0xFFFF`），覆盖从 `Magic` 到 `Payload` 末尾的全部字节，大端存储 |

- **最小帧长度**：`2 + 1 + 1 + 2 + 2 + 0 + 2 = 10 Bytes`
- **最大帧长度**：`10 + 4096 = 4106 Bytes`

## 2. 粘包、半包与错误恢复规则（拆包状态机）

在 `RingBuffer` 中按如下步骤循环解析：

1. **寻找帧头**：若缓冲区可读字节 `< 2`，返回 `kNeedMoreData`；若前 2 字节不是 `0xAA 0x55`，丢弃 1 字节继续滑窗查找。
2. **校验定长头部**：若可读字节 `< 8`（`Magic` ~ `PayloadLen`），返回 `kNeedMoreData`。
3. **合法性预检**：
   - 检查 `Version == 0x01`。
   - 解析大端 `PayloadLen`，检查 `PayloadLen <= 4096`。
   - 若版本或长度非法，判定为伪帧头，丢弃首字节 `0xAA` 并重新寻找下一个帧头。
4. **等待完整帧**：计算总帧长 `TotalLen = 10 + PayloadLen`；若可读字节 `< TotalLen`，返回 `kNeedMoreData`。
5. **CRC16 校验**：
   - 对前 `TotalLen - 2` 字节计算 CRC16，并与尾部 2 字节比对。
   - **校验通过**：提取完整帧，从缓冲区消费 `TotalLen` 字节，返回 `kOk`。
   - **校验失败**：记录错误计数，丢弃首字节 `0xAA` 并重新滑窗寻找帧头（防止单次比特错误锁死整条连接）。

## 3. 通用状态码（响应载荷首字节）

所有响应帧的 `Payload[0]` 统一为 `Status`（1 Byte）：

| 状态码 | 含义 |
| :--- | :--- |
| `0x00` | `OK`（执行成功） |
| `0x01` | `ERR_UNKNOWN_CMD`（不支持的命令字） |
| `0x02` | `ERR_INVALID_PARAM`（载荷长度或参数非法） |
| `0x03` | `ERR_HAL_FAILED`（底层硬件/节点读取或控制失败） |
| `0x04` | `ERR_INTERNAL`（服务端内部错误） |

## 4. 命令字一览

### 4.1 V1 已实现命令

| 请求 Cmd | 响应 Cmd | 名称 | 请求 Payload | 响应 Payload |
| :--- | :--- | :--- | :--- | :--- |
| `0x01` | `0x81` | **心跳 Ping/Pong** | 空（0B） | `Status(1B)` + `UptimeSec(4B, uint32 大端)` |
| `0x02` | `0x82` | **查询系统状态** | 空（0B） | `Status(1B)` + `CpuTempMilliC(4B, int32 大端，毫摄氏度)` + `MemTotalKB(4B, uint32)` + `MemAvailKB(4B, uint32)` |
| `0x03` | `0x83` | **控制板载 LED** | `LedId(1B)` + `State(1B: 0关/1开)` | `Status(1B)` + `LedId(1B)` + `ActualState(1B)` |
| `0x04` | `0x84` | **查询网关统计** | 空（0B） | `Status(1B)` + `ActiveConns(2B)` + `RxFrames(4B)` + `CrcErrors(4B)` |

### 4.2 V2 预留命令（协议向前兼容）

| 请求 Cmd | 响应 Cmd | 预留用途 |
| :--- | :--- | :--- |
| `0x10` | `0x90` | 读取自研 I2C/SPI 传感器实时数据 |
| `0x20` | `0xA0` | 查询本地 SQLite 离线缓存积压条数与 MQTT 在线状态 |
| `0x21` | `0xA1` | 触发离线缓存立即补传或调整采集周期 |

## 5. 示例帧（Heartbeat Ping）

- 请求：`Seq = 0x0001`，无载荷
- 待校验字节：`AA 55 01 01 00 01 00 00`
- 计算 CRC-16/MODBUS 后按大端追加 2 字节即构成完整 10 字节心跳请求帧。
